# engagement.json — schema v2 (the contract)

This is the single source of truth for the engagement pack. The brief states **inputs**
(days, rates, tier definitions, term). The shared lib (`generators/lib/commercials.js`)
states **money** — every total, scenario and the intro-offer sentence are DERIVED, never
read from the brief. If a figure can be computed, it is not an input.

Worked example: `assets/engagement.example.json` (Hensoldt). Reconcile + flexibility
proof: `node _selftest.js`.

## Non-commercial blocks (unchanged from v1)
`client` · `nova` · `sources` · `procurement` · `dates` · `output`. See the example.
`output.version` is always up-versioned per run; `output.gdriveFolder` is the delivery target.

## commercials (rebuilt — this is where the three flexibility axes live)

```
commercials: {
  currency: "CHF",          // ISO code; formats everywhere via lib/format
  dayRate: 2500,            // default rate; a line may override

  services: [ <line>, ... ],   // ARRAY of service lines (axis: SERVICES)
  licence:  { ... },           // the quoted offer (axis: LICENCE OPTIONS + CONTRACT LENGTH)
  tiers:    [ <tier>, ... ],   // variable-length ladder (axis: LICENCE OPTIONS)
  tierFootnote: "*Fair use cap.",
  runtimes: [ ... ]            // input; lib guarantees Salesforce Agentforce is present
}
```

### Service line — `pricingMode` selects the shape
One deal can mix lines (e.g. a fixed MVP line + a retainer + a managed-runtime line).

| pricingMode | Required fields | Payable = |
|---|---|---|
| `fixed-from-stages` | `stages[]`, `dayRate` | Σ(stage.days × dayRate) − discount |
| `t&m` | `stages[]`, `dayRate` | same, billed against estimate |
| `retainer` | `monthlyFee`, `months`, optional `callOff{dayRate,estimatedDays}` | monthlyFee×months (+ call-off estimate) |
| `call-off` | `callOff{dayRate,estimatedDays}` | dayRate × estimatedDays |
| `managed-runtime` | `monthlyFee`, `months` | monthlyFee × months |
| `free-partnership` | `stages[]`, `dayRate` | 0 (full value tracked + waived; name the consideration) |

Optional on any stage line: `discountPct` (0–100), `consultants`, `note`.
**Stage** = the MVP slate (narrative + sizing live together, one place):
`id, title, oneLiner, agentDoes, gatedAction, kpis, aiActClass, runtimeSystems,`
`status (confirmed|conditional), conditionNote, isBackup, backupNote, blastRadius,`
`elapsedWeeks, days, timeline{startWeek,endWeek,liveWeek,gate}`. `cost` is derived
(days×dayRate) unless explicitly overridden — an override that disagrees raises a warning.

### licence — quoted offer, structured term + intro-offer
```
licence: {
  quotedTier: "Domain",                 // must match a tiers[].name
  term: { initialMonths: 36, renewal: "..." },   // CONTRACT LENGTH — label derived ("3-year")
  domainDefinition: "...",
  introOffer: {                          // omit or {enabled:false} for none
    enabled: true, promoTier: "Enterprise", promoMonths: 6,
    priceBasis: "Domain", defaultsTo: "Enterprise", noticeWeeks: 4
  },
  addOns: [ { name, annualFee } ],       // e.g. marketplace; total derived
  overage: "...",
  year1: <number>                        // OPTIONAL override; default = quoted tier annual fee.
}                                        //   A blended year-1 is a commercial call — never invented.
```
The intro-offer **sentence** is generated by the lib from these fields and used identically
in the proposal, SoW, exec summary, proposal deck and summary deck (it was hand-typed in 4
files before). Change a field, every artefact updates.

### tiers — variable-N ladder
Array of `{ name, annualFee (number), agents, runs, runtimes, cdap, support }`.
Any length. The lib highlights the `quotedTier` automatically; generators render whatever N exist.

## Derived (do NOT put in the brief — `reconcile()` produces these)
- per-stage `cost`; per-line `payable` / `fullValue` / `discount` / `totalDays`
- `scenarios.confirmed | fullSlate | backupPath` → `{days, amount, note}` (filtered by stage status)
- `licence.term.label`, `licence.introOffer.sentence`, `licence.annualFee`, `addOnsTotal`
- `tiers[].highlight`, `runtimes` (Agentforce ensured), `year1Total`, `warnings[]`

## Reconcile guardrails (warnings, surfaced before delivery)
quoted tier not in ladder · stage cost ≠ days×rate · intro-offer references a missing tier ·
promoMonths > term · single-consultant 1-week stage > 5 days (aggressive).

## Commercial model: `ladder` vs `options`
`reconcile()` auto-detects the model. Provide **one** of:

- **Tier ladder** (Hensoldt) — `commercials.tiers[]` + `commercials.licence{quotedTier, introOffer}`.
  Licence slide = tier comparison; services slide = per-MVP breakdown + scenarios.
- **Commercial options** (Bosch) — `commercials.options[]`. Use when a deal is sold as
  alternative whole commitments rather than a tier ladder. The licence slide becomes an
  **options comparison** with the rows that actually differ, and the services slide shows the
  recommended option's delivery summary (days, co-investment, blended customer-pays) —
  decoupled from per-track pricing.

```
commercials.options: [
  { id, name, recommended: true,
    customerPaysYear1: 110000,        // what the customer pays Yr 1 (blended ok)
    term: { initialMonths: 12, renewal },
    deliveryDays: 20,                 // included delivery-support days (optional)
    coInvestment: 55000,              // Nova co-investment, not invoiced (optional)
    totalValueYear1: 165000,          // optional; derived = customerPays + coInvestment
    note }
]
```
Derived: `term.label`, `totalValue` (if omitted), recommended-flag (defaults to first),
`year1Total = recommended.customerPays`. Missing figures render as "—" (e.g. an option whose
delivery scope is still TBC). `commercials.licence` is optional in options mode — keep only
`domainDefinition`/`term` if you want them on the slide; `quotedTier` is not required.

## Generic timelines (no defined use case)  —  `build_timeline.js`
For prospects who don't have a use case yet. A separate, minimal brief drives an
archetype-based delivery-timeline deck (cover · phases · Gantt · next-steps). No MVPs.

```
{ client: { name },
  timeline: {
    archetype: "ingestion" | "greenfield" | "govern-in-place" | "hybrid",
    agents: 4,            // optional, for labelling
    totalWeeks: 8,        // optional; scales the default phase durations
    loi: true,            // optional; adds an LOI track
    kickoffAnchor: "on signature"
  },
  output: { fileStem, version } }
```
Archetypes live in `lib/timelines.js` (`expand()`); add or edit phase templates there. Hybrid
renders two parallel tracks. Run: `node build_timeline.js [brief.json]`.

## External dependency (`dates.gate`) — ask, never assume
Per engagement, confirm whether an external approval gates delivery (works council/Betriebsrat,
security review, regulator, customer board). This is **not** a default — Betriebsrat applies only
to high-risk HR cases, not most deals. Record the decision:
- `dates.gate: { name, date }` — a confirmed dependency (rendered under "DEPENDENCY").
- `dates.gate: null` — asked, none.
Absent entirely -> the generator warns, so the question gets asked on generation.

## Start mechanism (`procurement.start`) — ask, never assume
How the engagement begins is per-deal and was previously hardcoded to LOI. Confirm on generation
and record: `procurement.start = { type: "loi" | "po" | "contract", label?, note? }`. `loi` carries
"without commitment or prejudice" wording; `po` does not (a purchase order is a firmer commitment);
`contract` = signature authorises start. Legacy `procurement.loi` is still read as an LOI. Drives the
cover, phases, Gantt start-column and ask slide. The same `timeline.start` applies to build_timeline.js.

## Undefined MVPs (`defined:false`) — the 2-week rule
Mark a not-yet-scoped MVP `defined:false` and give it a planned `timeline.startWeek`. Its definition
falls due **2 weeks before its own start** (`DEFINITION_LEAD_WEEKS = 2`); with `dates.kickoff` (ISO) the
deadline renders as a date, otherwise as a week. It appears as a ◇ milestone on the Gantt (2 weeks
before the bar) and a "DEFINITION DUE" row on the ask slide. A `defined` MVP with no day estimate is a
preflight blocker (don't fabricate sizing).
